## الشريحة 1: بطاقة التعريف بالمشروع

* **اسم المشروع:** RASHAD AI -- رشاد AI.
* **الاسم الوصفي:** المنظومة الوطنية الذكية لإدارة وتحليل الاحتياج الزكوي ودعم القرار المؤسسي.
* **الجهة المستفيدة المستهدفة:** الهيئة العامة للزكاة -- ديوان الهيئة والمكاتب والفروع بالمحافظات والمديريات.
* **طبيعة المنتج:** منصة ويب مؤسسية متكاملة تعمل محلياً (On-Premises) لحفظ السيادة الرقمية الكاملة على البيانات الوطنية.
* **المرحلة الحالية:** نسخة أولية تجريبية مكتملة البناء والاختبار (Validated MVP Prototype).

## الشريحة 2: التحديات الميدانية والتشغيلية الراهنة

1. **اتساع رقعة الاحتياج وتفاوت الأولويات:** صعوبة التمييز الموضوعي السريع بين حالات الفقر الحرج والحالات المتوسطة عند توزيع المساعدات والمشاريع.
2. **مخاطر الازدواجية وتكرار الصرف:** تشتت السجلات بين الفروع وتعدد مصادر القيد، مما يرفع احتمالية تكرار الصرف لنفس الأسرة بالخطأ أو تشابه الأسماء.
3. **عبء الإدخال اليدوي وتدقيق الوثائق:** استنزاف وقت الباحثين الميدانيين في فحص آلاف وثائق الهوية والتقارير الطبية وإدخال أرقامها يدوياً.
4. **معضلة الفئات فاقدة الوثائق الرسمية:** وجود أسر نازحة ومعدمة لا تمتلك بطائق شخصية رسمية، مما قد يؤدي لحرمانها تقنياً إن لم يتوفر مسار توثيق مرن ومضبوط.
5. **ضرورة الشفافية والحوكمة الرقابية:** حاجة القيادة إلى لوحات مؤشرات جغرافية وإحصائية حية، وسجل تدقيق رقابي يثبت من أقر كل إجراء ومتى ولماذا.

## الشريحة 3: الرؤية الاستراتيجية والمبدأ الحاكم لمنظومة «رشاد AI»

> ### المبدأ الحاكم للمنظومة
> **المنصة أداة دعم قرار وتحليل إحصائي مساند، وليست جهة تصدر أحكاماً شرعية أو قانونية.**
> لا يتخذ النظام أي قرار قبول أو رفض أو حرمان آلي بحق أي مستفيد؛ وتظل القرارات النهائية بيد اللجان والمختصين البشريين المعتمدين رسمياً وفق الضوابط واللوائح الشرعية.

### القيمة المضافة للهيئة:
* **عدالة التوزيع:** توفير مؤشرات موضوعية موحدة تقيس الاحتياج بأربعة معايير متوازنة دون تحيز.
* **حماية أموال الزكاة:** محرك ذكي يرصد السجلات المشتبه بازدواجيتها ويحيلها للاعتماد الرقابي الثنائي.
* **سرعة الإنجاز:** تسريع قراءة الوثائق عبر OCR العربي بنسبة 70% مقارنة بالإدخال اليدوي.
* **الإنصاف والشمول:** حفظ حقوق الأسر فاقدة الوثائق عبر معرفات مؤقتة مقرونة بإفادات اللجان وعقال الحارات.

## الشريحة 4: البنية الفنية والأمان المؤسسي (Architecture & Privacy)

```text
  [ واجهة ويب عربية RTL متجاوبة ] <--- (بروتوكول آمن مشفر TLS) ---> [ خادم FastAPI REST API ]
                |                                                              |
    [ React 19 + TypeScript ]                                    [ نموذج صلاحيات RBAC + نطاق جغرافي ]
                                                                               |
                                                                  [ خادم PostgreSQL 18 محلي ]
                                                                               |
                                     +-----------------------------------------+-----------------------------------------+
                                     |                                         |                                         |
                         [ قاعدة بيانات مشفرة ]                     [ محركات الذكاء الاصطناعي ]                [ سجل التدقيق الرقابي ]
                      (بيانات الأسر والجغرافيا)               (مؤشر الاحتياج + كشف التكرار + OCR)              (Append-Only Audit Log)
```

### معايير الأمان المطبقة:
* **السيادة التامة:** المنظومة مصممة لتعمل محلياً (On-Premises) على خوادم الهيئة دون أي ارتباط بخدمات سحابية خارجية.
* **تجهيل بيانات المستفيدين:** حجب المعرفات الشخصية الصريحة تلقائياً عن محللي البيانات لضمان كرامة المستحقين.
* **سجل تدقيق غير قابل للتعديل (Append-Only):** توثيق كل عملية اطلاع أو تعديل أو اعتماد مع الطابع الزمني وهوية المنفذ.

## الشريحة 6: خارطة الطريق المقترحة للانتقال للتشغيل الرسمي (Transition Roadmap)

```mermaid
flowchart LR
    A["المرحلة 1: المراجعة المؤسسية والشرعية"] --> B["المرحلة 2: التكامل مع مصلحة الأحوال المدنية"]
    B --> C["المرحلة 3: تجربة ميدانية في مديرية ريادية"]
    C --> D["المرحلة 4: التعميم الشامل على مكاتب المحافظات"]
```

1. **المرحلة 1: المراجعة المؤسسية والشرعية (4 أسابيع):**
   * تشكيل لجنة مشتركة من قطاع المصارف وتقنية المعلومات لمراجعة أوزان مؤشر الاحتياج واعتماد مصفوفة الصلاحيات.
2. **المرحلة 2: الربط الشبكي والتكامل الحكومي (6 أسابيع):**
   * ربط النظام بقاعدة بيانات الأحوال المدنية للتحقق اللحظي من الأرقام الوطنية للمستفيدين.
3. **المرحلة 3: التشغيل التجريبي الميداني Pilot Run (8 أسابيع):**
   * إطلاق المنظومة تجريبياً في مديرية أو مديريتين لقياس أداء الباحثين الميدانيين وتدريب الكوادر.
4. **المرحلة 4: التدريب والتعميم الوطني:**
   * تجهيز خوادم الإنتاج الرئيسية بمركز بيانات الهيئة والتعميم التدريجي لعموم المحافظات.

## الشريحة 7: التوصيات والقرارات المطلوبة من قيادة الهيئة

للانتقال من مرحلة النموذج الأولي المثبت إلى الإعداد التشغيلي، نوصي باتخاذ القرارات التالية:
1. **تشكيل فريق عمل مشترك:** يضم ممثلين عن قطاع المصارف، إدارة تقنية المعلومات، والرقابة والتفتيش.
2. **اعتماد مصفوفة أوزان الاحتياج الرسمية:** لتحديث أوزان محرك القواعد وفق السياسة المعتمدة للهيئة.
3. **إقرار سياسة تصنيف وسرية البيانات:** لضبط مستويات تشفير وثائق الهوية والتقارير الطبية.
4. **توفير بيئة اختبار حكومية معزولة (Staging Environment):** لنشر النسخة التجريبية وإتاحة معاينتها للجان المختصة.
